# Идеи развития системы TKRP и оптимизация Workflow

## 1. Зафиксированные идеи развития мультиплатформенности

1. **Дообучение ML-модели вовлеченности на мультиплатформенных данных (`npm run ml:retrain`)**:
   - Датасет дополняется новыми признаками и прецедентами из Telegram (views, forwards, reactions) и Instagram (reels/video views, carousels, hashtags).
   - Обновление артефактов `data/ml/*.joblib` с валидацией версий признаков (`v2`).

2. **Социальный предпросмотр (Social Media Preview) в UI**:
   - Переключатель визуализации публикаций под целевую платформу:
     - **Telegram-вид:** имитация мессенджера (пузырь сообщения, спойлеры, моноширинный код, кнопки реакций).
     - **Instagram-вид:** срез текста до 125 символов с кнопкой «ещё...», карусель-слайдер.
     - **LinkedIn-вид:** заголовок статьи / PDF-документ слайды / B2B-карточка.
     - **VK-вид:** стандартная стена с вложениями.

3. **Интеграция с отложенным постингом и ботами**:
   - Прямой экспорт в Telegram-каналы через Telegram Bot API.
   - Экспорт в CSV/JSON для SMMplanner / SMMBox / Postman.

## 2. Реализуемая задача: Оптимизация порядка генерации плана (docs/workflow_plan.md)

### Проблема:
В исходной архитектуре вызов `/api/plan/generate` приводил к предварительной генерации полных текстов всех постов через серию долгих вызовов `generateMonthlyPublications` в LLM (30–60 секунд, тысячи токенов). Затем в `/api/plan/optimize` генетический алгоритм (GA) отбирал и мутировал признаки слотов (темы, цели, форматы, крючки), а `fillPlanWithBestPublication` повторно вызывал LLM для генерации текстов постов под победившие геномы. Тексты, созданные на этапе черновика, просто перезаписывались.

### Решение:
1. **Быстрый черновик (Fast Skeleton Mode):**
   - На этапе `/generate` выполняется только генерация сетки плана `generateSkeleton` (1 быстрый вызов LLM) и сборка слотов из RAG/шаблонов.
   - Месячные циклы генерации полного текста постов пропускаются. Черновик формируется за 1–2 секунды с сохранением тем, дат, форматов, целей и предиктов ML.
2. **Оптимизация перед генерацией текстов (Optimize First):**
   - Эволюционный алгоритм (GA) на этапе 1 и 2 оптимизирует признаки (структура, форматы, цели, крючки, списки).
   - Генерация полных текстов (`fillPlanWithBestPublication`) вызывается **только один раз — для финального победившего плана**.
3. **Возможность запуска `/optimize` без предварительного `/generate`**:
   - Если передан только `form_input` и `ragResults` (без готового `draft_content_plan`), оптимизатор сам собирает скелетон плана на лету.
