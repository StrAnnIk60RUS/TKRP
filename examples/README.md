# Примеры данных для тестирования

Эта папка содержит примеры данных для тестирования системы генерации контент-планов.

## 📁 Файлы

### 1. `project_data_example.json`
**Описание:** Пример заполненной формы проекта (данные вашего проекта)

**Содержит:**
- Информацию о производителе (CloudTech Solutions)
- Описание IT-проекта (CloudAnalytics Pro)
- Профиль целевой аудитории (B2B)
- Параметры контент-плана (сроки, бюджет, платформы)
- Настройки эволюционного алгоритма

**Использование:**
- Импортируйте этот файл в форму на сайте
- Или используйте как эталон для проверки структуры данных

---

### 2. `competitors_data_raw.json`
**Описание:** Пример СЫРЫХ данных от парсера (что реально может собрать парсер без LLM)

**Содержит:**
- Метаданные парсинга (дата, количество конкурентов, платформы)
- 4 конкурента с разными платформами
- Для каждого поста: контент, базовые метрики (лайки, просмотры, комментарии), хештеги, дата
- **НЕ содержит:** категорию контента, тональность, engagement_rate, стратегию контента (это обрабатывает LLM)

**Использование:**
- Это то, что должен предоставить Студент 1 (парсер)
- Используйте для понимания, какие данные реально может собрать парсер

---

### 3. `competitors_data_example.json`
**Описание:** Пример ОБОГАЩЕННЫХ данных после обработки LLM (для тестирования)

**Содержит:**
- Все данные из `competitors_data_raw.json`
- **Плюс:** категория контента (`content_category`), тональность (`tone`), расчетные метрики (`engagement_rate`, `click_through_rate`)
- **Плюс:** стратегия контента (`content_strategy`) для каждого конкурента
- **Плюс:** категория бизнеса (`category`: B2B/B2C/B2G)

**Использование:**
- Загрузите этот файл через форму "Загрузить данные конкурентов" для тестирования
- Или используйте для тестирования LLM-модуля напрямую
- **Важно:** Этот файл показывает, как должны выглядеть данные ПОСЛЕ обработки LLM

---

### 4. `combined_data_example.json`
**Описание:** Объединенные данные проекта и конкурентов (готовые для отправки в LLM)

**Содержит:**
- `project_input` - данные вашего проекта
- `competitors_data` - данные конкурентов
- `processing_metadata` - метаданные объединения

**Использование:**
- Используйте этот файл для прямого тестирования LLM-модуля
- Это то, что должно получиться после объединения `project_data_example.json` и `competitors_data_example.json`

---

## 🧪 Как использовать для тестирования

### Вариант 1: Через веб-форму

1. Откройте форму на сайте
2. Заполните форму вручную или нажмите "Пример: CloudAnalytics Pro" для загрузки примера
3. Загрузите `competitors_data_example.json` через кнопку "Загрузить данные конкурентов"
4. Нажмите "Отправить в LLM для обработки"

**Примечание:** `competitors_data_example.json` содержит уже обогащенные данные (с категориями, тональностью и т.д.). В реальной работе вы получите `competitors_data_raw.json` от парсера, и LLM должен будет обогатить эти данные.

### Вариант 2: Прямая отправка в LLM-модуль

1. Используйте `combined_data_example.json` напрямую
2. Отправьте его в ваш LLM-модуль для обработки
3. Проверьте результат генерации контент-плана

## ✅ Что проверять при тестировании

1. **Структура данных:**
   - Все обязательные поля присутствуют
   - Типы данных соответствуют ожидаемым
   - Даты в правильном формате (ISO 8601)

2. **Содержание данных:**
   - Тексты постов конкурентов реалистичны
   - Метрики находятся в разумных пределах
   - Категории и тональности соответствуют контенту

3. **Обработка LLM:**
   - LLM корректно извлекает паттерны из данных конкурентов
   - Генерируется онтология с правильной структурой
   - Создаются посты, адаптированные под ваш проект

4. **Результат:**
   - Контент-план содержит посты для всех указанных платформ
   - Посты соответствуют бюджету и срокам
   - Применяются успешные паттерны конкурентов

---

## 🔧 Примечания

- Все даты указаны в формате ISO 8601 (YYYY-MM-DDTHH:mm:ss)
- Метрики (engagement_rate, views, likes) основаны на реалистичных значениях для B2B-контента
- Хештеги и категории соответствуют реальным практикам в соцсетях
- Данные конкурентов охватывают разные платформы и типы контента для полноты анализа

## ⚠️ Важное различие

**`competitors_data_raw.json`** - это то, что реально может собрать парсер:
- ✅ Текст поста, дата, базовые метрики (лайки, просмотры, комментарии)
- ✅ Хештеги, упоминания, длина текста
- ❌ НЕТ категории контента, тональности, engagement_rate, стратегии

**`competitors_data_example.json`** - это обогащенные данные после обработки LLM:
- ✅ Все данные из raw файла
- ✅ Плюс категория, тональность, расчетные метрики, стратегия
