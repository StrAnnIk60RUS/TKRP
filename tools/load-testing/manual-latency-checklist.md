# Чеклист ручных замеров латентности API (TKRP)

Использование: сервер запущен (`npm run dev` из корня или только API из `apps/api`). Зафиксировать в таблице протокола: дата, ОС, версия Node.js, наличие `OPENROUTER_API_KEY`, объём корпуса прецедентов (число записей в `data/precedents/publications.json` или размер файла).

Перед серией замеров выполнить один «прогревочный» запрос к каждому эндпоинту (не включать в статистику).

## Эталонные запросы

Подставить `<HOST>` (например `http://127.0.0.1:<PORT>`). Для POST — заголовок `Content-Type: application/json`.

| № | Метод и путь | Тело / примечание |
|---|----------------|-------------------|
| A | `GET /health` | без тела |
| B | `GET /api/precedents/summary` | без тела |
| C | `POST /api/precedents/search` | `{"query":"тестовый запрос прецедентов","limit":8}` |
| D | `GET /api/plan/draft/current` | без тела |
| E | `POST /api/plan/generate` | минимально корректный `form_input` из примеров проекта; требует LLM — замерять отдельно |

## Порядок записи

1. Для каждого запроса A–D зафиксировать время от начала до получения полного тела ответа (мс), код HTTP.
2. Повторить серию N раз (например N = 10 для базовой линии; для параллельной нагрузки — см. ниже).
3. Вычислить среднее и максимум по каждому эндпоинту.

## Параллельная нагрузка (упрощённо)

В POSIX-оболочке можно использовать несколько фоновых `curl` с `-w "%{time_total}\n"` или утилиту `hey` / Apache Bench, если установлены. На Windows — PowerShell `Measure-Command { Invoke-WebRequest ... }` в цикле или несколько окон терминала.

Критерий для таблицы 5.4 в ПЗ: при Y параллельных запросах C среднее время не превышает согласованного порога; доля ответов 5xx — 0 при исправной среде и доступном OpenRouter.

## Объёмный режим

Перед замером C и `GET /api/precedents` подготовить копию большого корпуса в тестовом каталоге `data/precedents/` (не править рабочую выгрузку без резервной копии). Зафиксировать размер `publications.json` в МБ и время ответа C и полного snapshot.

## Надёжность (без автоматизации)

- Блокировка OpenRouter: временно убрать ключ из окружения или заблокировать исходящий HTTPS к провайдеру; выполнить один запрос к маршруту с LLM; зафиксировать код и поле `error`; снять блокировку и повторить успешный сценарий.
