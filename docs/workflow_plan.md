# План работы по переработке хода работы программы

## Цель
Изменить порядок работы так, чтобы сначала происходила работа генетического алгоритма с признаками, а потом генерация постов с отобранными лучшими признаками (убрать предварительную генерацию постов через LLM перед запуском GA).

## Текущий порядок (после вызова /generate затем /optimize):
- /generate: Вызывает generateDraftPlanBatched → создает draft_content_plan через LLM и RAG (без GA)
- /optimize: Вызывает unHierarchicalOptimization → выполняет:
  * Этап 1 GA: Оптимизация структуры плана (выбор признаков: topic, format, objective, tone, hasCta, creativity) → создает optimizedPlan с публикациями
  * Этап 2 GA: Оптимизация признаков каждой публикации (детальная работа с признаками постов)
  * Этап 3: Выбор лучших публикаций из этапа 2 → финальный план с отобранными лучшими признаками

## Необходимые изменения (Вариант A: убрать предварительную LLM генерацию):
1. **Модифицировать эндпоинты /generate и /generate-batched** (pps/api/src/modules/planning/routes/planRoutes.js):
   - Вместо вызова generateDraftPlanBatched возвращать только предварительно обработанные данные (например, orm_input, результаты RAG поиска прецедентов, возможно, сгенерированный skeleton без публикаций) или просто подтверждение получения данных.
   - Цель: избежать генерации постов через LLM до запуска GA.

2. **Изменить optimizeContentPlanEvolution** (pps/api/src/modules/planning/services/evolutionary/planEvolution.js):
   - Обеспечить возможность работы без входного draft_content_plan (генерировать базовые публикации с нуля).
   - Изменить функцию expandBasePublications и связанные с ней функции так, чтобы они генерировали базовые публикации на основе обязательных полей из orm_input и данных из прецедентов (без reliance на существующий draft).
   - На этапе 1 GA функция pplyGenomeToPlan должна корректно создавать публикации на основе генов (topic, format, objective, tone, hasCta, creativity), используя данные из RAG и LLM для заполнения summary, key_message и т.д.

3. **Опционально: refactor draftPlanGenerationPipeline.js**:
   - Разделить функции генерации skeleton и генерации публикаций для возможности генерировать только основу (skeleton) для оптимизации.

## Тестирование:
- Запустить /optimize без предварительного /generate и убедиться в корректной работе (используя данные из orm_input и, возможно, кэшированные прецеденты).
- Сравнить результаты с текущим потоком /generate затем /optimize.
- Убедиться, что качество планов не ухудшилось и, ideally, улучшилось за исключением ненужной LLM генерации.
