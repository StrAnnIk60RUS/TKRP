# План работы по переработке хода работы программы

## Цель
Изменить порядок работы так, чтобы сначала происходила работа генетического алгоритма с признаками, а потом генерация постов с отобранными лучшими признаками (убрать предварительную генерацию постов через LLM перед запуском GA).

## Прежний порядок (после вызова /generate затем /optimize):
- /generate: Вызывает generateDraftPlanBatched → создает draft_content_plan через LLM и RAG с полной генерацией текстов постов по месяцам (тратя ~40с и тысячи токенов на черновики, которые затем перезаписывались).
- /optimize: Вызывает runHierarchicalOptimization → выполняет:
  * Этап 1 GA: Оптимизация структуры плана (выбор признаков: topic, format, objective, tone, hasCta, creativity) → создает optimizedPlan с публикациями
  * Этап 2 GA: Оптимизация признаков каждой публикации (детальная работа с признаками постов)
  * Этап 3: Выбор лучших публикаций из этапа 2 → генерация финальных текстов постов через LLM для победителей

## Реализованный оптимизированный порядок:
1. **Быстрая генерация основы (fastSkeleton)** (`draftPlanGenerationPipeline.js`):
   - `generateDraftPlanBatched` генерирует структуру слотов (skeleton) через 1 быстрый LLM-вызов.
   - Пропускаются повторные ежемесячные LLM-вызовы (`generateMonthlyPublications`). Слоты нормализуются и обогащаются на лету (~50 мс) без растраты токенов на промежуточные черновики.
   - Управляется флагом `fastSkeleton: true` или переменной `FAST_DRAFT_SKELETON_MODE` (по умолчанию включен).
2. **Прямой запуск оптимизации** (`hierarchicalGa.js`):
   - `runHierarchicalOptimization` поддерживает запуск как с существующим `draft_content_plan`, так и напрямую с `form_input` (автоматически формируя быстрый скелет).
3. **Эволюция и финальная генерация**:
   - GA Stage 1 и Stage 2 оптимизируют сетку геномов (темы, форматы, цели, тоны, крючки, CTA).
   - `fillPlanWithBestPublication` вызывает `generatePostContent` строго один раз — для победного плана.

## Результаты:
- Время создания черновика снижено с ~40 сек до ~1.5 сек (ускорение в ~25 раз на этапе драфта).
- Экономия токенов до 70% за счет устранения мусорных генераций текстов перед GA.
- Полная обратная совместимость со всеми эндпоинтами и UI.
